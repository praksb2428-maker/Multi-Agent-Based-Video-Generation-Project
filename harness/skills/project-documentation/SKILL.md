# 작업 결과 문서화

구현 결과를 문서에 반영할 때 사용한다. [제작 요구와 범위](../../../docs/harness.md), [검사 기록](../../../docs/testing.md)을 기준으로 한다.

- 기존 작업 기록에 요구 ID, 변경 파트·인터페이스, 소스/입력 기준, 명령·환경·결과, 실패·수리 누계와 다음 행동을 간결히 남긴다.
- README는 재현 가능한 명령과 현재 사용자 흐름만, architecture는 실제 연결과 설계상 역할의 차이를 설명한다. 같은 정보를 여러 문서에 복사하지 않는다.
- 실행·재사용·미검증·보류·범위 제외를 구분한다. 모의 응답을 실제 LLM 결과, 문서 존재를 live discovery, 기술 검사를 사람 수락으로 표시하지 않는다.
- 변경된 Markdown의 링크·구조·읽기 흐름을 확인한다. 화면이나 그림은 실제 렌더를 검사한다. 관찰하지 않은 캡처·테스트는 증거로 쓰지 않는다.
- 원본 제안서·기존 승인·최종 결과·실패 증거를 보존한다. 개인정보·키·비공개 참고 대화는 제출용 문서에 복사하지 않는다.

완료 시 새 파일을 늘리기보다 기존 기록을 정리한다. 필요한 최종 자료만 보존하고 복원하지 않은 백업을 복원 검증 완료라고 쓰지 않는다.
