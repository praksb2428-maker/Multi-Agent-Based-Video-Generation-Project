# ADR 0008: 로컬 연출·범용 프롬프트 준비

- **상태:** 순차 개발 요청 범위 구현, 독립 검토 대기
- **배경:** 사용자의 기획안에 맞춘 순차 개발 요청에서 기획 수정·재승인 다음은 연출과 프롬프트 전달이다. 실제 영상 제공자·모델·비용·호출 승인은 아직 미정이다.
- **선택지:** A. 기존 Python 로컬 규칙과 JSON 계약으로 다음 전달 경계 구현 / B. 실제 모델·영상 API·별도 프레임워크 연결
- **선택과 이유:** A. 외부 서비스·비용 경계를 유지하고 현재 승인 기획의 장면을 도출한다. AI 연출·성능을 주장하지 않는다.
- **영향:** 버전1 `direction`은 `local_rule_template` 출처, 부모 기획 내용 해시·조건·문맥·장면을 담고 조명·오디오를 `local_default`로 표시한다. `prompts`는 현재 승인 기획에서 도출한 값과 입력 연출 전체를 canonical JSON 바이트로 비교한 뒤 기획 해시와 연출 SHA-256을 기록한다. 직렬화는 UTF-8, 키 정렬, `ensure_ascii=False`, `allow_nan=False`, 구분자 `,`·`:`다. 수동 변경한 연출은 허용하지 않으며 수정은 기획의 수정·재승인 후 재도출한다.
- **프롬프트 경계:** 전체 훅·이야기와 원 장면 대본·배경·행동·카메라·길이·조건을 전달하고 금지 목록은 별도 `must_avoid`에 둔다. 결과 상태는 `draft`, 제공자·모델·견적·제작 승인은 `null`이다. 별도 연출 승인 단계나 자동 제작 승인은 추가하지 않는다.
- **제약:** 제공자별 입력 serializer·실제 모델·미디어·가격·실행 권한은 후속 결정이다. [ADR 0005](0005-offline-services.md)와 [0006](0006-sdk-mock.md)의 실제 호출 금지 경계, [0007](0007-plan-revision.md)의 재승인을 유지한다. 새 의존성·저장 기술은 도입하지 않는다.
- **결정 근거:** 개인(사용자)의 순차 개발 요청 안 내부 연결 구현. 새로운 외부 서비스·비용 승인은 아니다.
- **날짜:** 2026-10-30
