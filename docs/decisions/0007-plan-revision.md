# ADR 0007: 명시적 기획 수정과 재승인

- **상태:** 요청 범위에 따른 구현, 독립 검토 대기
- **배경:** 사용자가 “이제 기획안에 맞춰서 다음에 만들어야 할 기능도 순서대로 진행해줘”라고 요청했다. 제안서의 사용자 수정 요청 반영과 변경 후 재승인을 우선 연결한다.
- **선택지:** A. 로컬에서 사유와 명시적 교체 JSON을 반영 / B. 자연어 피드백을 실제 모델로 해석
- **선택과 이유:** A. 실제 모델·유료 호출을 허용하지 않은 현재 경계를 유지한다. `hook`, `story`, 전체 `scenes` 교체만 받고 조건·출처·비용·승인은 바꾸지 않는다. 자연어 사유는 기록만 하며 AI 해석을 주장하지 않는다.
- **영향:** 원본과 별도 새 초안을 저장하고 이전 승인을 해제한다. `revision` 버전 1의 회차·부모 내용 SHA-256·사유·변경 필드를 새 승인 해시에 포함한다. 해시는 기존과 같은 UTF-8, 키 정렬, `ensure_ascii=False`, 구분자 `,`·`:`의 JSON 직렬화로 계산한다. 메타데이터 없는 기존 schema 1 기획 해시는 그대로 유지한다. 부모 해시는 연결 기록이며 원본 파일 보유 없이 과거 내용의 진실성이나 신원을 증명하지 않는다.
- **제약:** 프레임워크·의존성·저장 기술·제작 승인·유료 호출 규칙은 바꾸지 않는다. [ADR 0005](0005-offline-services.md)와 [0006](0006-sdk-mock.md)의 실제 호출 금지 경계를 유지한다.
- **결정 근거:** 개인(사용자)의 순차 개발 요청 범위 안 구현. 외부 서비스·비용에 대한 새 승인은 아니다.
- **날짜:** 2026-10-30
