# ADR 0006: OpenAI SDK 모의 응답 단계

- **상태:** 확정(도입 범위), 구현 후보 독립 검토 대기
- **배경:** 사용자가 “OpenAI SDK를 추가하고 실제 비용이 발생하지 않는 모의 응답 테스트부터 진행해줘”라고 요청했다.
- **선택지:** A. SDK와 메모리 전송 모형으로 요청·응답 계약부터 검증 / B. 실제 API 키와 유료 호출을 연결해 검증
- **선택과 이유:** A. 실제 SDK 직렬화와 응답 파싱을 확인하되 서비스 호출과 결제를 하지 않는다. `openai==3.41.0`과 직접 사용하는 `httpx==0.28.1`을 프로젝트 가상환경에 설치한다. 별도 에이전트 프레임워크는 채택하지 않는다.
- **영향:** 기존 `draft`·`approve`를 유지하고 모의 전용 `draft-mock`을 추가한다. 고정 모의 URL과 가짜 키, `MockTransport`, 재시도 0회를 사용한다. 승인·입력 조건·비용·출처는 응답이 아닌 앱이 정한다. 요청의 모델 문자열은 대화에서 선택한 `gpt-6.1-sol`이지만 실제 모델 실행·접근 권한·품질·비용 검증은 아니다. 제안서 원본의 모델 표기는 이번에 수정하지 않는다.
- **제약:** SDK 3.41.0의 내부 환경 설정 모듈만 빈 환경으로 격리한다. 프로세스 전역 환경을 바꾸거나 실제 키를 읽지 않는다. 이 호환 지점은 버전 업데이트·동시 실행 전 재검증한다. [ADR 0005](0005-offline-services.md)의 실제 외부 호출·유료 검증 전 별도 결정 조건은 유지한다.
- **결정자:** 개인(사용자)
- **날짜:** 2026-10-30

구현 인수 상태는 [테스트 기록](../testing.md#sdk-모의-응답-후보)에 따르며 도입 승인이 결함 있는 후보의 최종 채택을 뜻하지 않는다.

사용자는 최초 수리 한도 소진 뒤 발견한 `null` fixture의 잘못된 성공 대체 문제에 한해 추가 수정 1회를 명시적으로 허용했다. 이 예외는 해당 결함과 회귀 검사에만 적용하며 다른 결함·실제 API 호출의 권한이나 한도를 늘리지 않는다. 기본 수리 2회와 예외 1회 이력은 보존한다.
