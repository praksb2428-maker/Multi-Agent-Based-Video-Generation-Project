# ADR 0015: GUI의 명시 로컬 AI 기획·대본 생성

- **상태:** 사용자 요청 범위의 구현·검사 완료, 부모의 실제 GUI 생성1회와 두 승인 경계 확인. 독립 검토와 사용자 채택은 별도 기록한다.
- **배경:** J에서 검증한 고정 Ollama provider를 기존 GUI의 입력·승인·저장 흐름에 연결한다.
- **선택지:** 기존 CLI만 유지 / 기존 GUI의 기획 방식 선택에 실제 로컬 생성 추가. 새 모델·프레임워크·설치는 도입하지 않는다.
- **선택과 이유:** 사용자 원문 “이제 GUI에서도 로컬 모델로 기획·대본을 생성할 수 있게 연결해줘. 기존 양식과 기획·제작 승인 단계는 유지하고, 비용이 발생하지 않는 범위에서 진행해줘.”에 따라 후자를 적용한다. 기본 템플릿·입력 양식·레이아웃·별도 두 승인은 유지한다.
- **영향:** local_ollama 모드를 명시적으로 선택한 새 기획 생성만 기존 create_local_draft를 호출한다. 앱 소유 입력/출처/승인/비용을 다시 확인한 뒤 미승인 초안을 저장한다. 조회/새로고침/승인/명시 수정은 호출하지 않는다. 실제 기획과 모의 영상, 형식 검사와 내용 품질을 화면에서 구분한다.
- **실패·복구:** 모델 서버 없음/응답 시간 초과/버전·모델 불일치/기획 검증 실패는 한국어 오류이며 새 작업을 저장하지 않는다. 기존 작업을 보존하고 사용자가 서버·입력을 확인한 뒤 버튼을 다시 누른다. 자동 retry/fallback/pull/서버 시작/승인/제작은 없다.
- **범위·수리:** K는 GUI 연결의 새 범위로 추가 수리 최대2회다. 이전 J2/2+schema예외1/1·G/E/D2/2·I/H0/2는 보존한다. J provider 코드와 대본 사실성 개선을 이름만 바꿔 수리하지 않는다. 실제 브라우저의 가상 이야기 주제1회 생성은 K의 새 통합 검사이며 이전 재활용 샘플을 재생성하지 않는다.
- **보존:** 원본 기획안·CLI·기존 provider·스킬/workflow·의존성·모의 제작 도메인·과거 기록을 보존한다. 유료 API·AI 연출/영상/TTS·추가 설치·전역 설정·자동 시작은 제외한다. 실제 내용/사용자 채택은 별도다.
- **결정자:** 개인(사용자)의 위 명시 요청. 작고 기존 형식을 유지하는 모드 추가는 이 범위의 구현 선택이다.
