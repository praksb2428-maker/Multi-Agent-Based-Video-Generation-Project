# 로컬 숏폼 제작과 중간보고서 시연

## 시작과 종료

저장소 루트 PowerShell에서 실행한다. 기존 Python 가상환경과 FFmpeg/FFprobe를 사용하며 새 패키지·모델을 설치하지 않는다.

```powershell
.\.venv\Scripts\python.exe -X utf8 shorts_web.py
```

브라우저에서 `http://127.0.0.1:8765`로 접속한다. localhost 별칭·외부 주소 접속은 받지 않는다. 종료는 실행한 터미널에서 `Ctrl+C`다. 화면을 닫는 것만으로 서버가 종료되지는 않는다. 포트 충돌이면 다른 프로그램을 끄지 말고 `--port 8766`처럼 새 포트를 지정한다. 검증용 임시 서버는 작업 후 소유권을 확인하고 종료한다.

업데이트 전에 켜 둔 서버는 Python 코드를 계속 메모리에 보관한다. 새 **API 연결 모의 테스트**를 사용하려면 해당 서버를 종료한 뒤 위 명령으로 다시 실행해야 한다. 이번 검증에서는 기존 사용자8765 서버를 재시작하지 않고 별도 최신8766 서버를 사용한 뒤 종료했다.

참고 [온라인 오디오 변환기](https://online-audio-converter.com/ko/)의 검은 상단바·중앙 회색 작업판·원형 단계·파란 주요 버튼을 숏츠 작업실에 적용했다. 위쪽에 입력·기획 방식과 저장 작업, 아래에 현재 기획·가상 견적·제작·결과를 배치했다. 네 기획 방식과 모든 기존 입력, 두 승인, 명시 수정·재승인·재제작, 영상·파일 다운로드와 확인 기록을 유지한다. 로그인·업로드·오디오 변환 기능을 새로 도입한 것은 아니다. 참고 사이트에 자료를 전송하지 않는다.

## 한 편의 흐름

자료를 함께 시험하려면 기획 생성 전에 **모의 자료 조사 사용**을 켜고 **모의 자료 검색**을 누른다. 제목·주소·요약·미검증 경고를 확인한 뒤 기존 생성 버튼을 누른다. 기본은 OFF이며 실제 인터넷을 검색하지 않는다. 출처 주소는 합성 예시 텍스트로만 표시한다. 주제뿐 아니라 길이·비율·스타일·시청자·금지어·가상 예산을 바꾸거나 선택을 껐다 켜면 다시 검색한다. 검색 결과가 없으면 생성하지 않고 조건을 바꾸거나 조사를 끈다. 저장된 기획에서도 같은 자료와 출처를 볼 수 있으며 자료를 바꾸려면 새 기획으로 시작한다. 기존 기획·제작 승인은 아래처럼 각각 진행한다.

1. 주제·길이·비율·스타일·시청자·금지 요소·가상 예산을 입력하고 기획 방식을 선택해 **기획 초안 만들기**를 누른다. 기본은 규칙 템플릿이다. **API 연결 모의 테스트 · OpenAI SDK**는 키나 모델 서버 없이 Python SDK의 요청·합성 응답을 확인하며 실제 Codex 생성은 아니다. **로컬 AI 실제 생성 · Qwen 3.5 4B**는 별도로 실행한 Ollama 모델 서버를 사용한다. [서버 실행 안내](../README.md#실행)를 따른다. 참고 자료가 없어도 시작한다.
2. 훅·스토리·세 장면을 확인하고 **이 기획 승인**을 누른다. 수정 초안을 먼저 만들 수도 있다.
3. **연출·프롬프트·견적 준비**로 현재 기획에 맞는 내용을 만든다. 프롬프트와 가상 견적을 확인한다.
4. 승인자 표기·사유를 직접 적고 **이 내용의 모의 제작 승인**을 누른다. 승인 표기는 실제 신원 인증이 아니다.
5. 별도로 **승인된 내용으로 모의 제작**을 눌러 MP4·SRT·장면 정보·품질 검사 파일을 만든다.
6. 영상과 자막을 확인한 뒤 확인 완료 또는 수정 요청을 직접 기록한다. 기술 통과만으로 자동 수락하지 않는다.
7. 수정 요청이면 새 훅·스토리·장면 값을 직접 입력해 수정 초안을 만든다. 기획 승인→새 견적→새 제작 승인→새 모의 제작을 다시 거친다. 기존 결과는 보존한다.

수정 사유는 기록이며 AI가 해석하지 않는다. 실제 로컬 기획 생성도 자동 승인·제작으로 이어지지 않는다. 생성 중에는 중복 버튼 실행을 막고, 조회·새로고침·기획/제작 승인·명시 수정에서는 모델을 다시 호출하지 않는다. AI 초안의 사실관계와 표현을 확인/수정한 뒤 기획을 승인한다. 색상 카드의 MOCK 글자는 그대로일 수 있고 대본 수정은 SRT·장면 JSON에 반영된다. 영상은 무음이고 실제 인물·배경 생성·내레이션 동기화는 검사하지 않는다.

## 저장·오류·재개

화면의 저장된 작업 목록에서 선택하거나 새로고침해 이어간다. 서버를 재시작해도 JSON 기록과 파일 해시를 검사한다. 다른 화면에서 바뀐 요청, 수정된 파일, 임의 경로·추가 필드, 단계 건너뛰기는 거부한다.

API 모의 응답이 거부되거나 조건을 위반하면 새 작업을 저장하지 않고 한국어 오류를 표시한다. 기존 작업은 유지한다. 입력을 확인한 뒤 사용자가 새 생성을 명시적으로 요청하며 자동 재시도·실제 API 대체는 없다. 화면에는 API 키 입력란이 없고 서버도 키·endpoint·live 전환 필드를 받지 않는다. 조회·재시작·승인·수정은 SDK 요청을 추가로 만들지 않는다.

Ollama 모델 서버가 꺼져 있거나 버전/모델이 다르거나 응답이 기획 조건을 통과하지 못하면 한국어 오류를 표시하고 새 작업을 저장하지 않는다. 기존 작업과 선택한 기획은 보존한다. 서버와 입력을 확인한 뒤 생성 버튼을 다시 명시적으로 누르는 것이 복구 경로이며 자동 시작·다운로드·재시도·유료 대체는 없다. 웹 화면 서버와 Ollama 모델 서버는 별개이며 사용 후 각각 종료한다.

모의 승인은 테스트용 1시간 유효기간이다. 시간이 지난 뒤 기존 결과의 기술 검사는 가능하지만 새 제작은 막는다. 이 첫 GUI에서는 만료된 미제작 작업을 새 입력으로 다시 시작한다. 실패한 제작도 부분 파일을 보존하고 해당 작업을 중단한다. **새 작업**으로 시작하는 것이 복구 경로이며 자동 재시도·폴더 삭제는 없다.

현재 결과의 MP4·SRT·장면 JSON·품질 보고·manifest만 내려받을 수 있다. 새 버전이 현재가 되면 이전 결과는 디스크에 보존하지만 이 GUI의 다운로드는 현재 검증 결과만 제공한다. 과거 결과·원본 제안서를 화면으로 공개하지 않는다.

## 중간보고서 시연

시연은 5~10초의 합성 입력으로 진행한다. 다음 세 화면이면 두 승인과 결과를 보여줄 수 있다.

- 기획 승인 대기: 주제·조건·훅·장면·승인 대기 상태가 보이는 화면.
- 제작 승인 대기: 현재 프롬프트·가상 견적과 별도 승인 버튼이 보이는 화면.
- 결과 확인 또는 수정본 승인 대기: 모의 영상·파일·기술 결과와 사용자 확인, 또는 수정본의 재승인 대기가 보이는 화면.

캡처의 실제 경로와 실행 상태는 작업 기록에 남긴다. 캡처가 실제로 만들어지고 확인되기 전에는 보고서에 시연 완료라고 쓰지 않는다. 테스트 수는 [검사 기록](testing.md)의 해당 실행을 참조한다.

보고서 설명 예시: “주제 입력부터 기획·제작 승인, 로컬 합성 결과 검사와 수정 후 재승인까지 GUI로 연결했다. 모델 응답과 견적은 모의 방식이며 실제 AI 영상·음성 API는 호출하지 않았다.”
