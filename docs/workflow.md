# 개인·AI 작업 흐름

이 문서는 **작업 과정**의 기준이다. 목표와 현재 범위는 [프로젝트 브리프](project-brief.md), 어떤 결정을 개인에게 물을지는 [결정 기준](decisions/README.md), 검사 대상과 명령은 [테스트 계획](testing.md)을 따른다. 이번 단계에서는 개인이 흐름을 관리하며 **한 CLI에서 AI가 작성자 → 검토자 역할을 순서대로 전환**한다. 별도 에이전트나 병렬 실행을 전제하지 않는다.

## 단계와 책임

| 단계 | 개인 | AI의 입력 → 출력 |
| --- | --- | --- |
| 1. 요청 확인 | 목표·제약·원하는 결과를 제공한다. | 요청, 제안서, 기존 파일 → 현재 상태와 완료 조건을 확인한다. 추측한 구현을 사실로 쓰지 않는다. |
| 2. 영향과 계획 정리 | 범위가 맞는지 판단한다. | 관련 파일·결정 기록 → 영향받는 파일, 필요한 검사, 미정 사항을 간결하게 정리한다. |
| 3. 중요 결정 확인 | [결정 기준](decisions/README.md)에 걸리는 선택을 확정하거나 보류한다. | 선택지·장단점·추천 이유·영향 → 개인에게 질문하고 답을 ADR에 기록한다. 답이 필요한 변경은 그 전까지 진행하지 않는다. |
| 4. 작업 | 필요한 범위·자료를 제공한다. | 확정된 범위 → 최소 변경을 적용한다. 기존 파일과 무관한 변경을 보존한다. |
| 5. 검사 | 필요한 경우 결과물을 직접 확인한다. | 변경 사항·[테스트 계획](testing.md) → 실행 결과와 실패 원인을 확인한다. 실패 시 아래 수정 한도를 따른다. |
| 6. 문서 갱신 | 설명과 실제 결과가 맞는지 본다. | 확인된 결과 → README, 브리프, 테스트 계획, ADR 중 영향을 받은 문서만 갱신한다. 미구성 명령이나 미실행 검사를 성공으로 표시하지 않는다. |
| 7. 개인 채택 | 결과를 채택하거나 보완·보류를 지시한다. | 변경 파일, 검사 결과, 미정·위험·다음 조치 → 간결한 완료 보고를 제출한다. AI의 완료 보고가 개인의 최종 채택을 대신하지 않는다. |

## 작성자와 검토자

| 역할 | 입력 | 출력 | 수정 범위 |
| --- | --- | --- | --- |
| 작성자(AI) | 개인 요청, 제안서·브리프, 확정 ADR, 관련 코드·문서 | 범위 안의 파일 변경, 검사 근거, 변경 설명 | 요청과 확정 결정이 허용한 파일만 수정한다. 이번 하네스 문서 단계에서는 앱 기능을 수정하지 않는다. |
| 검토자(AI, 같은 CLI의 다음 단계) | 요청·완료 조건, 작성자 변경·diff, 검사 결과, 결정 기록 | 누락·충돌·검증 부족을 짚은 검토 결과와 수정 요청 | 먼저 읽기 전용으로 검토한다. 발견 사항은 작성자 역할에서 범위 내 수정하고 다시 검사한다. 중요한 결정은 개인에게 돌린다. |
| 개인 | AI의 계획·질문·검토 결과 | 중요 결정과 최종 채택·보류 | 프로젝트 범위·비용·자료 사용 등 권한이 필요한 선택을 확정한다. |

## 검사 실패와 중단

최초 검사 실패 뒤 원인을 확인하고 **추가 수정은 최대 2회**만 한다. 각 수정 뒤 같은 관련 검사를 다시 실행한다. 두 번째 추가 수정 뒤에도 실패하면 더 수정하지 않고 실패 명령, 관찰 결과, 추정 원인, 영향, 다음 조치를 기록해 개인에게 보고하고 중단한다. 새 범위나 중요 결정이 필요하면 먼저 개인에게 확인한다.

`AGENTS.md`와 이 문서는 작업 절차를 설명한다. **규칙 파일만으로 도구 권한, 파일 접근, 결제 또는 외부 서비스 사용이 기술적으로 강제되지는 않는다.** 실제 권한은 실행 환경과 도구 설정에 따르며, 개인 확인이 필요한 결정을 우회하는 근거로 문서를 사용하지 않는다.
