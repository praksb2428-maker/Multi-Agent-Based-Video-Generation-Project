# 강의 과제: 숏츠 프로젝트의 개발 하네스

기준일: 2026-11-16. 기존 프로젝트와 원본 제안서를 유지하며 개발용 스킬·사용 기록을 정리한 보고서다. 실제 LLM·AI 영상 생성 완성을 뜻하지 않는다. GitHub 업로드는 실행하지 않았다.

## 과제와 현재 구성

[강의 과제 안내](https://github.com/hsmu-jeongeun/llm-programming/blob/main/harness/project_assignment.md)의 P1–P5를 기존 프로젝트에 적용한다. 제안서는 사용자가 확정한 [Video_Production_Project.md](../Video_Production_Project.md)를 그대로 사용하며 `proposal.md` 사본은 추가하지 않는다.

| 단계 | 프로젝트에 남긴 것 | 현재 상태 |
| --- | --- | --- |
| P1 제안서·결정 | [브리프](project-brief.md), [초기 질문](open-questions.md) | 기존 근거 활용. 이번 요청에 새 기술·비용 결정 없음 |
| P2 규칙·책임 | [AGENTS](../AGENTS.md), [workflow](workflow.md), [ADR](decisions/README.md) | 기본 스킬 경로·개발 역할 연결 갱신 |
| P3 스킬 | [계획](../.agents/skills/project-plan/SKILL.md)·[검증](../.agents/skills/project-check/SKILL.md)·[문서화](../.agents/skills/project-docs/SKILL.md) | 프로젝트 경로에 작성, 코드·검사·승인 권한 구분 |
| P4 환경·검사 | 기존 가상환경, 테스트, [검사 기준](testing.md) | 환경·모듈 로딩·핵심 14개 실제 검사 |
| P5 시험 운영 | 아래 사용 기록·점검 경로·회고 초안 | 파일 직접 읽기 수행, 자동 발견 미확인 |

개발 하네스의 역할은 작성자·검토자·개인이다. 작성자는 허용 범위만 변경하고, 검토자는 소스·테스트를 고치지 않으며, 개인은 중요한 결정과 최종 채택을 맡는다. 서비스의 콘텐츠 기획·연출·제작 역할과 구분한다.

## 스킬 실제 사용 기록

새 스킬이 현재 세션의 목록에 자동 추가됐다고 가정하지 않았다. 강의 P5의 대체 방법에 따라 **각 실제 SKILL.md를 읽고 절차를 수행**했다. `$project-plan` 등의 자동 발견·호출 성공을 주장하지 않는다.

| 순서 | 실제 수행 | 산출물 |
| --- | --- | --- |
| 1 project-plan | 제안서·규칙·기존 결정·파일 확인, 범위·보존·검사·미정 정리 | `workspace/plan.md` |
| 2 project-check | 기존 환경 확인, 모듈 로딩·핵심 검사 실행, 명령·종료·로그 기록 | `workspace/checks.md`, `bootstrap-log.md`, 원본 로그 |
| 3 project-docs | 확인된 결과를 규칙·사용 안내에 반영, 회고 초안 작성 | `workspace/docs-update.md`, `reflection.md`, 이 보고서 |

이번 검사는 다음 명령으로 실제 실행했다. 저장소 루트에서 실행하며 설치·외부 키가 필요하지 않다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "import src.shorts, src.direction, src.mock_production; print('offline modules loaded')"
.\.venv\Scripts\python.exe -X utf8 -W error::ResourceWarning -m unittest discover -s tests -p test_shorts.py -v
```

- 환경: Python 3.12.1, 기존 openai 3.41.0·httpx 0.28.1 유지.
- 모듈 로딩: `offline modules loaded`, 종료 코드0.
- 핵심 검사: **14개 통과, 1.308초, 종료 코드0**. 입력·금지 요소·길이·기획 승인 결속·CLI 저장/거부/원본 보존을 포함한다.
- 스킬 구조·링크·제품 보존의 최종 확인과 원본 로그는 `workspace/checks.md`에 연결한다. 이 문서는 제출용 요약이며 원시 로그 전체를 복사하지 않는다.

구조 검사에서는 스킬3개에 사용한 두 scalar 필드·계약과 관련 Markdown14개·로컬 링크99개를 확인했다. 제품·테스트·기존 참고 스킬37파일과 이전 증거136개는 해시가 같았다. 기본 스킬 검증기는 PyYAML이 없어 실행하지 못했으므로, 이번 단순 형식의 대체 구조 검사와 구분해 기록했다. 새 설치는 하지 않았다.

기존102개 검사 이력과 GUI·영상 시연은 제품이 변경되지 않은 범위의 기존 근거다. 이번에 전체102개나 영상 제작을 새로 실행하지 않았다. 실제 모델·API·TTS·자동 스킬 발견의 성공으로 확대 해석하지 않는다.

## 규칙·승인·자료 보존

기획 승인과 별도 모의 제작 승인, 변경 후 재승인은 기존 제품 코드에 유지한다. 이번 작업에서 앱 코드·테스트·의존성·GUI 자산·기존 참고 스킬·원본 제안서를 수정하지 않는다. 시작 SHA 기준과 최종 비교로 보존을 확인한다. 이전 승인·결과·실패 기록도 그대로 둔다.

공개용 보고서에는 비공개 대화, 개인 정보, API 키, 계정·환경 변수 내용을 넣지 않는다. `workspace/`는 Git 제외 경로이므로 현재 문서에 명령과 실제 결과 요약을 남긴다. 원시 기록을 Git에 무조건 추가하거나 자동 업로드하지 않는다.

새 세션에서 확인할 때는 같은 프로젝트를 작업 폴더로 열고 `$project-plan`, `$project-check`, `$project-docs`를 각각 요청한다. 보이지 않으면 경로·YAML을 확인하고 SKILL.md를 직접 읽은 수행으로 기록한다. 이 안내는 이번 세션에서 자동 발견을 검증한 결과가 아니다.

## 사실 기반 회고 초안

아래는 확인된 선택과 작업을 바탕으로 AI가 정리한 **사용자 확인 전 초안**이다. 개인의 감상이나 직접 수행 경험을 대신 주장하지 않는다.

1. **프로젝트에 맞춘 규칙**: 기획 승인과 제작 승인을 구분하고, 수정된 결과는 새 승인에 연결하도록 했다. 모의 실행과 실제 AI 제작의 결과도 구분했다.
2. **중요한 선택과 이유**: 실제 모델·유료 API 연결을 보류하고 모의 응답부터 검증하기로 했다. 비용 없이 입력·출력과 승인 절차를 먼저 확인하는 범위다.
3. **AI가 대신 결정하지 않는 일**: 제공자·모델 설치, 유료 호출, 외부 전송, 공개·배포와 최종 수락은 명시적인 결정이 필요하다.
4. **확인한 것과 남은 것**: 기존 환경·핵심14개 검사는 실제 실행했다. 실제 모델·TTS·영상 API와 새 세션의 자동 스킬 발견은 검증하지 않았다.
5. **다음 요청의 순서**: project-plan으로 범위·미정을 정하고, 작성 후 project-check로 검사한다. project-docs로 사실을 기록하고 검토·개인 확인을 거친다.

## 최종 점검과 남은 확인

독립 검토자의 요구별 판정과 근거는 로컬 `workspace/harness-review.md`에 별도로 남긴다. 검사 통과나 AI의 보고가 개인의 최종 채택을 대신하지 않는다. 사용자 감상·회고의 최종 문구와 제출·업로드는 본인 확인이 남아 있다.
